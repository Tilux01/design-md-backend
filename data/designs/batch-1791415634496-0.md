# CardioLife Mobile App - System Design Specification (`design.md`)

This document provides a highly detailed, high-fidelity technical design specification for reconstructing the **CardioLife** mobile application. It covers three screens: **Splash/Onboarding**, **Home/Booking Dashboard**, and **Appointment Details**.

The design is optimized for a **full-screen edge-to-edge mobile experience** (eliminating mock phone device frames) using modern responsive web standards or cross-platform mobile frameworks (such as React Native, Flutter, or standard Tailwind CSS / HTML5).

## 7. Interactive Micro-Interactions & Animations

To provide a premium app experience, apply these programmatic motion parameters:

### 7.1 Screen Transitions
*   **Slide & Fade**: When moving from Screen 1 to Screen 2, the background should cross-fade smoothly (`transition: duration-500 ease-in-out`), and Dashboard elements should trigger a cascade slide-up animation.

### 7.2 Micro-Interactions
*   **Pulse Wave (Screen 1)**: The EKG line in the background uses an SVG stroke path animation mimicking a continuous heartbeat monitor:
    ```css
    @keyframes heartbeat {
      0% { stroke-dashoffset: 1000; }
      100% { stroke-dashoffset: 0; }
    }
    .ekg-line {
      stroke-dasharray: 1000;
      animation: heartbeat 8s linear infinite;
    }
    ```
*   **3D Heart floating**: The main anatomical heart graphic should drift up and down slowly over a 4-second period using CSS `translateY` transform (`ease-in-out`) to simulate breathing.
*   **Chip/Filter Interaction**: Clicking inactive filter chips (Screen 2) scale-transforms the item slightly (`scale-95`) before adding the active color state instantly with an organic ease.
*   **Card Hover Expansion**: Hovering/touching the clinical cards on Screen 2 and 3 triggers a slight elevation lift and soft drop shadow expansion (`shadow-soft-lg`).
