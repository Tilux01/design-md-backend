# UI/UX Technical Design Specification: Fantasy Sports Companion App

This design specification document outlines the layout, color system, typography, components, asset requirements, and interactive behaviors for creating an exact, pixel-perfect clone of the provided mobile application design. 

---

## 1. Executive Design Overview
The application is a high-fidelity, modern **Fantasy Sports & Tournament Platform**. Its visual language relies on bright gradients, high-contrast action elements (buttons, badge pill indicators), rounded structural containers, and clean information hierarchy. The interface targets high engagement through clear data visualizations and instant, tactile feedback loops.

---

## 2. Global Style Guide & Token System

### 2.1 Color Palette
The app uses a clean, light mode aesthetic with deep colorful gradients to establish brand presence and separate distinct zones of interaction.


### 2.2 Typography Guide
The design uses a clean, geometric sans-serif typeface optimized for readability on mobile displays across varying text weights.

*   **Primary Typeface:** **Plus Jakarta Sans** (Alternative: **Inter**)
    *   *Fallback Stack:* `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`
*   **Font Weights Used:**
    *   `400` (Regular) — Body text, captions, secondary details.
    *   `500` (Medium) — Navigation tabs, form labels, primary card values.
    *   `600` (Semi-Bold) — Subheadings, primary CTA labels.
    *   `700` (Bold) — Screen titles, hero numbers, statistical metrics.

#### Type Scale
| Token | Font Size | Line Height | Weight | Usage |
| :--- | :--- | :--- | :--- | :--- |
| `--text-h1` | `24px` | `32px` | `700` | Profile Usernames, Featured Header Text |
| `--text-h2` | `18px` | `24px` | `700` | Section Titles (e.g., "Recommended Leagues") |
| `--text-body` | `14px` | `20px` | `400` | General content reading, subtitles |
| `--text-button` | `14px` | `18px` | `600` | Primary & Secondary button texts |
| `--text-caption` | `11px` | `14px` | `500` | Small data labels, dates, secondary stats |

### 2.3 Layout & Grid System
To maintain consistent framing across multiple viewports without showing safe area cutouts or simulated physical hardware borders:
*   **Canvas Width:** Fluid up to `428px` (Standard maximum mobile viewport context). Runs full-screen edge-to-edge.
*   **Base Grid Margin:** `16px` padding horizontally on outer canvas boundaries.
*   **Gutters:** `12px` to `16px` vertical gaps between stacked blocks.
*   **Border Radius System:**
    *   `--radius-sm`: `8px` (Badges, mini buttons)
    *   `--radius-md`: `16px` (Default cards, league crest frames)
    *   `--radius-lg`: `24px` (Main card displays, action sheets)
    *   `--radius-pill`: `9999px` (Action pills, status elements)

## 4. Visual Interactions & Motion Design

An immersive experience depends on responsive user feedback, smooth transitions, and polished structural animations.

```
                  ┌──────────────────────┐
                  │      User Tap        │
                  └──────────┬───────────┘
                             │
                  ┌──────────▼───────────┐
                  │ Scale Component to   │
                  │ 0.97 (Active State)  │
                  └──────────┬───────────┘
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
┌───────────────────────┐         ┌───────────────────────┐
│     Screen Change     │         │   Leagues Grid Join   │
├───────────────────────┤         ├───────────────────────┤
│ Slide-Left Transition │         │ Button text transitions│
│ (300ms ease-out)      │         │ "JOIN" ➔ "JOINING..." │
└───────────────────────┘         └───────────────────────┘
```

### 4.1 Tactile State Interactions
*   **Interactive Taps (Cards, Action Buttons):**
    *   Transition scale reduction on dynamic trigger states: `transform: scale(0.97)` to indicate responsiveness.
    *   Transition curve rule: `transition: transform 0.2s cubic-bezier(0.25, 1, 0.5, 1)`.
*   **Hover states (Web/Desktop Viewports):**
    *   Primary CTAs smoothly shift using standard color values: `filter: brightness(1.05)` or a light `box-shadow` depth expansion.

### 4.2 Page Screen Transitions
To match native mobile app behavior, route-to-route transitions should use slide-left animations.
*   **Page Exit / Entry Animation Style:**
    *   *Enter Screen:* Slides inward from coordinate `X: 100%` directly to position `X: 0%`. Duration: `300ms`, easing pattern: `cubic-bezier(0.16, 1, 0.3, 1)`.
    *   *Exit Screen:* Slide outward slightly to position `X: -30%` while simultaneously fading out.

### 4.3 Loading States (Skeleton Shimmers)
To handle slow data loading, content boxes should show grey placeholder shapes with an active animation wash.
*   **Background Base Color:** `#E2E8F0`
*   **Shimmer Gradient Wave:** `linear-gradient(90deg, #E2E8F0 25%, #F1F5F9 50%, #E2E8F0 75%)`
*   **Animation Behavior:** Infinite linear loop across `1.5s` duration, with keyframes changing gradient translation from left to right.

## 5. UI/UX Asset & Asset Export Guidelines

To ensure the app looks sharp and clear across all screen sizes and resolutions, follow these guidelines for icons and graphical assets:

### 5.1 SVG Vector Guidelines
All interface icons (such as settings gears, home indicators, notifications, back arrows, and search glasses) must use SVG format rather than PNGs.
*   Vector export viewports must be squared exactly to standard dimensions (e.g., `24px` x `24px` bounding boxes with centered graphic designs).
*   Maintain a uniform path style across all UI vectors: set line weights to a fixed thickness (`2px`) with rounded endpoints (`stroke-linecap: round; stroke-linejoin: round`).
